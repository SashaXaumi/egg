# Egg Project Context

This is a lite fork of `carpetsage/egg`, slimmed to one app: the Egg Inc. Coop Tracker (`eicoop`), under a ferret-themed dark UI, deployed to Netlify via GitHub Actions. The full repo-level overview lives in the root `README.md` — read that first if you need install/build/deploy details.

## Scope

**Only work in `eicoop/`, `lib/`, `ui/`, or `protobuf/` files.** The `wasmegg/` tree from upstream has been removed; there's nothing to do there.

For most UI work the relevant tree is `eicoop/`. Touch `lib/api/` or `protobuf/ei.proto` only when syncing a game-version change from upstream (see "Tracking upstream" in the root README).

## Repo layout

pnpm workspaces. The packages are:

- `lib/` — Egg Inc. API client (`lib/api/`), generated proto types (`lib/proto/`, **gitignored**; regenerated by `make -C lib` from `protobuf/ei.proto`), and game-logic helpers (contracts, prophecy eggs, earning bonus, etc.).
- `ui/` — shared Vue components (`BaseIcon`, `BaseInfo`, etc.).
- `eicoop/` — the Vite + Vue 3 app, `name: coop-tracker`. Everything user-facing lives in `eicoop/src/`.

## Commands

Run from `eicoop/` unless noted:

- Dev server (HMR): `pnpm dev` — listens on http://localhost:5173, vite proxy maps `/api/*` to `https://www.auxbrain.com/*`.
- Type check: `pnpm vue-tsc --noEmit` — must pass before any commit that touches Vue/TS.
- Production build: `pnpm build` (type-check + build) or `pnpm fastbuild` (build only; CI uses this).
- Regenerate proto (after editing `protobuf/ei.proto`): `make -C lib`.

If `pnpm` isn't on PATH in a non-interactive shell, the local binaries work directly: `eicoop/node_modules/.bin/vite` and `eicoop/node_modules/.bin/vue-tsc`.

## Stack

- Vue 3 — components use Options API with `defineComponent({ setup() { … } })`, plus `<script setup lang="ts">` in a few newer ones. Tailwind for utility classes; design-token CSS in `eicoop/src/ferret.css` for the theme. Vite is the bundler. Pinia for stores (`eicoop/src/stores/*`). dayjs for dates. protobufjs for proto encode/decode. pako for gzip in the proto envelope.

Game API:

- `lib/api/index.ts` — every endpoint (`requestFirstContact`, `requestCoopStatus`, `requestContractsInfo`, `resolveContractsInBackup`, …) is here.
- `lib/api/version.ts` — `APP_VERSION` / `APP_BUILD` / `CLIENT_VERSION` constants the game server checks. Bump in lockstep when adopting an upstream proto update.

## Standing conventions

- **Comment-don't-delete.** Mute removed code instead of deleting it so the user can re-enable later. For Vue markup that's referenced by name (e.g., a registered component): comment out the usage but keep the import + registration. For markup containing `var(--…)` tokens, an HTML `<!-- -->` comment isn't valid — wrap the block in `<template v-if="false">…</template>` instead. For helper functions, prefix with `//` line comments.
- **Don't touch wasmegg/.** It's gone in this fork and the build doesn't need it.
- **`fromDashboard` prop.** When the same component renders in both the standalone coop page and embedded inside `UserDashboard`, gate per-card chrome (refresh, footer, timestamps) on `!fromDashboard` so the dashboard provides single controls at the bottom (the den block).

## Tracking upstream (game-version sync)

When the game updates and the dashboard breaks, the fix exists upstream. Walkthrough lives in the root `README.md`; in short:

1. `git fetch upstream && git log --oneline HEAD..upstream/main` to find the fix commits.
2. Adopt `protobuf/ei.proto` verbatim from upstream.
3. Run `make -C lib` to regenerate `lib/proto/index.{js,d.ts}`.
4. Update `lib/api/version.ts` constants.
5. Port the helper additions in `lib/api/index.ts` and the call-site fixes in `eicoop/src/lib/` and components. Most upstream diff lines touch `wasmegg/*` and are not applicable here — skip them.

The commit `ed36a247` ("Sync game 1.35.7") is a worked example.
